Resurrection Lab

Pick a project, read its autopsy, choose a revival path and work through the plan.

How the Lab works

Four steps from a forgotten repository to a working project. Rule-based, and honest about what it cannot see.

1

Scan

Reads a public GitHub repo: README, open issues, test files and the last push date.

2

Diagnose

Turns evidence into findings marked Healthy, Issue or Unknown, each with its source.

3

Plan

Builds prioritized tasks (P1 to P3) with rough effort ranges from the findings.

4

Revive

Accept tasks, tick them off, follow the timeline, and mark the project revived with a link.

Frontend-only build. Projects are stored in this browser. GitHub scan uses the public GitHub API. Revival plans are rule-based, not AI-generated. Sample projects are labeled.
